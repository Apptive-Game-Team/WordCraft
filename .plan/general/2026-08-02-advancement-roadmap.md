# 2026-08-02 — 고도화 로드맵

- Date: 2026-08-02
- GitHub Issue: none yet
- Owning repository: WordCraft
- Status: Draft

## Goal

지금은 대칭 프로토타입이다. 두 사람이 LAN에서 채집·건설·생산·전투를 하고 본진 파괴로
승부가 난다. 그러나 여섯 진영이 서로 다르게 플레이되지 않고, 진영을 고를 수도 없다.

이 로드맵은 프로토타입을 게임으로 만드는 순서를 정한다. 기준은 하나다. **화면에서
진영이 구별되는 것이 아니라 손에서 구별되어야 한다.**

## 현재 상태

검증된 것:

- 결정론 시뮬레이션. 같은 입력 로그가 CoreCLR과 Unity Mono에서 같은 해시를 낸다.
- P2P 락스텝. 손실 20%·중복 10%·지터 40ms 링크에서 400틱 해시 일치, desync 감지,
  핸드셰이크 거부, 타임아웃 처리.
- 채집, 건설, 생산 큐, 그리드 A*, 전투, 승리 조건, 대칭 맵.
- Unity 클라이언트. 카메라, 박스 선택, 명령 발행, HUD, 스프라이트 94종.

검증되지 않은 것:

- **사람이 마우스로 끝까지 플레이한 대전.** 지금까지 검증은 전부 스크립트 입력
  로그와 배치 모드 두 프로세스였다. 명령 발행 경로는 헤드리스로만 확인됐다.

없는 것:

| 항목 | 현재 |
|---|---|
| 진영 선택 | `MatchScenario`가 세계수 대 지옥불로 하드코딩 |
| 진영별 차이 | `FactionData`의 스탯이 여섯 진영 동일 |
| 진영 메커니즘 6종 | 문서에만 있음 |
| 방어 건물 발사 | `CombatSystem`이 `EntityKind.Unit`만 순회 |
| 인구 상한 | `Role.Supply`는 데이터만, 규칙 없음 |
| 기술 단계 | T1/T2/T3 게이트 없음 |
| 역할 슬롯 | 진영당 역할 하나씩. 아트 7종이 갈 곳 없음 |
| 시작 UI | 커맨드라인 `-join <ip>`뿐 |

## Acceptance Criteria

- 매치 시작 시 각 피어가 진영을 고르고, 그 선택이 핸드셰이크에 포함되어 불일치가
  틱 0 전에 거부된다.
- 여섯 진영이 각자의 고유 메커니즘으로 플레이된다. 동족전 시나리오가 리플레이
  하네스에 들어가고 두 번 실행해 틱별 해시가 같다.
- 방어 건물이 사거리 안의 적을 공격한다.
- 인구 상한과 기술 단계가 생산을 실제로 제한한다.
- 아트가 있는 자산에 전부 슬롯이 있다.
- 커맨드라인 없이 매치를 시작하고 끝내고 다시 시작할 수 있다.
- 새로 추가된 모든 상태 필드가 `World.Hash()`에 들어간다.

## Non-goals

- 밸런스 조정. 진영 메커니즘이 전부 들어오기 전의 밸런스는 측정할 대상이 없다.
- 인터넷 대전, NAT 통과, 매치메이킹.
- 캠페인, PVE, 진행도, 계정.
- 3인 이상 대전. 현재 2인 가정은 `// ponytail:` 두 곳에 표시돼 있다.

## 단계

### 0단계 — 검증

**0-1. 사람이 하는 대전 한 판.** 두 클라이언트를 띄우고 마우스로 끝까지 플레이한다.
여기서 깨지는 것이 다음 우선순위를 정한다. 이 단계를 건너뛰고 위에 쌓으면 검증되지
않은 토대 위에 계속 얹는 것이 된다.

### 1단계 — 구조 (진영 차이를 담을 그릇)

메커니즘보다 먼저다. 그릇이 없으면 메커니즘을 넣을 곳이 없다.

**1-1. 진영 선택.** `MatchConfig`에 피어별 진영을 넣고 핸드셰이크에서 교환한다.
`MatchScenario`가 하드코딩 대신 그 값을 읽는다. 진영은 이미 엔티티 상태로 해시되므로
새 해시 필드는 없다.

**1-2. 역할 슬롯 확장.** 역할당 하나가 아니라 목록으로 바꾼다. 지금 갈 곳 없는 자산:
균열 파수병, 해일 인도자, 멸종 슬라임 3종, `ElectricTower`, `RockTurret`, 마도 정찰기.
진영마다 유닛 구성이 다른 것이 설계인데 현재 구조는 동일 역할 집합을 전제한다.

**1-3. 방어 건물 발사.** `CombatSystem`이 건물도 순회하게 한다. 이동하지 않고 사거리
안의 적을 공격한다. 스탯은 이미 테이블에 있다.

**1-4. 인구 상한.** 본진 +10, 공급 건물 +8, 상한 200. 생산과 성장이 상한에 걸린다.
현재 인구를 상태로 들고 해시한다.

**1-5. 기술 단계.** T1은 본진, T2는 생산 건물, T3는 기술 건물이 연다. 건물 파괴 시
해당 단계 유닛의 생산이 막히되 이미 나온 유닛은 남는다.

### 2단계 — 진영 메커니즘

`docs/FACTION-MECHANICS.md`의 순서를 따른다. 새로 필요한 상태가 적은 것부터다. 각
단계마다 동족전 시나리오를 리플레이 하네스에 넣고 두 번 실행해 해시를 비교한 뒤
다음으로 넘어간다.

| 순서 | 진영 | 메커니즘 | 새 상태 |
|---|---|---|---|
| 2-1 | 물 슬라임 | 일제 사격 | 없음. 매 틱 계산 |
| 2-2 | 돌 골렘 부족 | 잔해 | 만료 틱 |
| 2-3 | 지옥불 군단 | 군단장 | 쿨다운, 자손 수 |
| 2-4 | 인간 마법 문명 | 징발 | 포획 진행도, 중립 소유권 |
| 2-5 | 세계수 정령 | 성장 | 성장 타이머, 목표 종류 |
| 2-6 | 차원 유랑종 | 통로 | 도착 지점, 소환 만료 |

2-3에서 공중 규칙이 처음 필요하다. 근접은 공중에 닿지 않고, 공중은 지형과 잔해를
무시한다. 2-4는 그 규칙이 이미 있어야 성립한다. 인간의 유일한 대공 수단이 맵 위의
중립 꼬마돌을 포획해 만드는 `Towerback`이기 때문이다.

### 3단계 — 플레이 표면

여기서부터 사람이 쓸 수 있는 물건이 된다.

- **3-1. 시작 화면.** 직접 IP 입력, 진영 선택, 접속 상태 표시. 커맨드라인 제거.
- **3-2. 결과 화면과 재시작.** 지금은 승부가 나도 HUD 한 줄이 전부다.
- **3-3. 전투 가독성.** 체력바, 선택 표시, 사거리 표시, 피해 피드백.
- **3-4. 미니맵.** 통로로 후방에 유닛이 도착하는 진영이 있으므로 없으면 대응이 불가능하다.
- **3-5. 사운드.** WordOnline에 21개 자산이 있다. 소유권은 확인됐다.

### 4단계 — 콘텐츠와 깊이

- **4-1. 밸런스.** 여기서 처음으로 목표가 된다. 진영별 스탯을 분리하고 동족전이 아닌
  대전을 반복해 조정한다.
- **4-2. 맵.** 중립 꼬마돌 배치가 인간 진영의 전제다. 자원 배치와 길목이 잔해
  메커니즘과 맞물린다.
- **4-3. 리플레이 저장과 재생.** 입력 로그와 해시 체크포인트가 이미 있으므로 파일로
  쓰고 읽는 것이 남았다.
- **4-4. 관전.** 락스텝 설계 문서에 이미 정의돼 있다. 확정 프레임을 소비하되 배리어에
  참여하지 않는다.

## Validation

- 단계마다: `dotnet build`, `dotnet run --project Replay`,
  `dotnet run --project Host -- selfcheck`, Unity `ViewSelfCheck`.
- 진영 메커니즘마다: 동족전 시나리오를 리플레이 하네스에 추가하고 두 번 실행해 틱별
  해시 비교. 의도적 변조로 발산이 감지되는지도 함께 확인.
- 골든 해시가 움직이면 두 런타임이 독립적으로 같은 값을 내는 것을 먼저 확인한 뒤에만
  상수를 고친다.
- 1단계와 2단계가 끝날 때마다 사람이 하는 대전을 한 판씩 한다.

## Risks & Rollback

- **결정론.** 새 규칙마다 새 상태가 생긴다. 해시에 빠뜨리면 desync가 조용히 생기고
  발견이 늦다. 상태 필드를 추가할 때 `World.Hash()`를 같이 고치는 것이 규칙이다.
- **역할 구조 변경의 파급.** 1-2는 `FactionData` 인덱싱과 `ViewSelfCheck` 순회를
  동시에 건드린다. 다른 작업과 겹치지 않게 단독으로 진행한다.
- **밸런스를 앞당기려는 유혹.** 메커니즘이 없는 상태의 밸런스 조정은 나중에 전부
  버려진다. 4-1 전에는 하지 않는다.
- **2인 가정.** 3인 이상은 `Net/Transport.cs`와 `Net/LockstepSession.cs`의
  `// ponytail:` 두 곳을 풀어야 한다. 로드맵 밖이다.
- 롤백은 단계마다 머지 되돌리기. 배포된 빌드가 없어 호환성 부담이 없다.

## Release Order

1. 0단계 검증
2. 1-1 진영 선택 → 1-3 방어 건물 → 1-4 인구 → 1-5 기술 → 1-2 역할 슬롯
3. 2단계 메커니즘 여섯 개, 순서대로
4. 3단계 플레이 표면
5. 4단계 콘텐츠

1-2를 1단계 마지막에 두는 이유는 파급이 가장 크고, 그 전 항목들이 현재 구조에서
동작하는 것을 먼저 확인하는 편이 낫기 때문이다.

## Open Questions

- 진영 선택을 매치 시작 시 고정할지, 랜덤 옵션을 둘지.
- 역할 슬롯을 목록으로 바꿀 때 인덱싱을 어떻게 안정적으로 유지할지. 현재는
  `faction * RoleCount + role`이고 값이 해시된다.
- 방어 건물이 공중을 공격하는지는 진영마다 다르다. 대포는 지상 전용, `Towerback`은
  공중 전용이다. 이 구분을 스탯에 넣을지 별도 플래그로 둘지.
- 인구 상한 200이 이 맵 크기에 맞는지.
- 사운드를 어느 단계에서 넣을지. 없어도 플레이는 되지만 피해 피드백이 사운드에
  의존하는 부분이 있다.
