# 2026-10-15 — Host arena 명령 추가

- Date: 2026-10-15
- GitHub Issue: #170
- Status: Implemented

## Goal

Host에서 여섯 진영의 순서 있는 36쌍을 AI 대 AI로 실행하고, 매 틱 hash를 두 실행 사이에서 비교한 뒤 승률을 출력한다.

## Non-goals

- Sim, Replay, Client 변경과 밸런스 수치 조정.
- thread 병렬 실행과 시뮬레이션 성능 변경.

## Context / Constraints

- 각 판은 `MatchScenario.Build`로 만들고 두 피어에 `SetPeerAi`를 적용한다.
- 기본값은 쌍마다 한 판, 6000틱, seed `0xC0FFEE`이다. 같은 쌍의 판마다 seed에 game index를 더한다.
- 쓰기 범위는 issue #170의 여섯 파일과 이 plan 파일로 제한한다.

- [x] **Step 0: Recon**: issue #170, Host dispatch와 SelfCheck, World 공개 API, MatchScenario, Replay의 solo 실행 확인.
- [x] **Step 1: Implementation**: `Host/Arena.cs`에 인자 검사, 판 실행과 hash 비교, 쌍별 결과와 종합 표를 추가했다. Host dispatch와 SelfCheck를 연결하고 문서 두 곳을 고쳤다.
- [x] **Step 2: Tests**: build 0 warning, selfcheck OK, 지정한 두 판 실행 OK, 36쌍 Release 실행 9.11초.

## Validation

- **Commands to run:** `dotnet build`; `dotnet run --project Host -- selfcheck`; `dotnet run -c Release --project Host -- arena -a Humans -b Hellfire -games 2`; `dotnet run -c Release --project Host -- arena`.
- **Expected output:** build 0 warning, selfcheck OK, 쌍별 결과와 종합 승률, 모든 판에서 동일한 hash, 전체 실행 2분 미만.

## Risks & Rollback

- **Risks:** 36쌍을 각각 두 번 실행하고 매 틱 hash를 계산하므로 Release wall time이 2분을 넘을 수 있다. 동족전에서 피어별 결과를 같은 진영에 합산하는 규칙을 명확히 해야 한다.
- **Rollback steps:** arena 및 문서 commit을 `git revert`한다.
